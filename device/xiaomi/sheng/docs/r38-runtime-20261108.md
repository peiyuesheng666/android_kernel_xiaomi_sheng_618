# r38 charging initialization runtime verification

On 2026-11-08, the authorized r38 installation attempt stopped at the live
baseline guard before any partition write: vendor already matched the sealed
r38 image, rather than r37. The existing r38-20261108-135556 operation log
records the earlier successful vendor_b/vbmeta_b writes and reboot. This turn
confirmed the installed result and performed a controlled reboot; it did not
repeat those writes or weaken the baseline guard.

Both frozen `-VerifyRuntime` runs passed all seven partition hashes, the exact
init RC, original SystemUI, native-DMA property and face-preview resources.
The recorded first boot shows the charging node wait succeeding in the boot
action at kernel time 7.479430 seconds after 2497 ms, while the driver was
creating its attributes. That boot's ID was
af9b1323-25de-4495-8748-d3691c44926e.

The controlled reboot produced boot ID f526546c-dd24-4dde-9d91-d6a50dd02cd6.
Both health services were discoverable at the first shell observation, uptime
9.32 seconds. `sys.boot_completed=1` was observed at 32.95 seconds, before
restarting adbd as root for partition/node readback. No temporary chmod/chown,
charging-node write, service restart or property workaround was performed.
The wait succeeded at kernel time 6.830351 seconds after 2374 ms. Node ownership
and mode were 1000:1000/0660, with input_suspend still 0. The original SystemUI,
SurfaceFlinger and system_server PIDs remained unchanged through the 115.35
second observation. SELinux stayed Enforcing, the crash buffer was empty, and
the latest ANR files remained the previously recorded r37 files.

This validates the r38 charging initialization fix for the observed boots.
It does not establish unlimited boot reliability, face enrollment, charging
limit behavior, recovery battery reporting, or completion of a normal product
or module build. Face enrollment and its protected-preview composition crash
remain unresolved; no camera was opened and no image was acquired here.

The machine-readable receipt is runtime-r38-charging-order-20261108.json.
Raw evidence remains outside Git under reports/device/r38-runtime-20261108;
the two frozen verifier logs are referenced by the receipt.

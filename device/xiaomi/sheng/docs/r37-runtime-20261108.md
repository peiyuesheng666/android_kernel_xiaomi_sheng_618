# r37 actual enrollment and startup failures

r37 was installed on ca10ede3/sheng slot b. Seven partition hashes, the
native-DMA property and installed face-preview resources were read back.
SELinux stayed Enforcing. Full product and normal module builds remain
uncompleted.

The user confirmed that preview now appears, but enrollment repeatedly asks
for the face to be placed inside the frame and never completes. It subsequently
soft-restarted. At 05:48:27 UTC SurfaceFlinger's RenderEngine thread aborted:
`Could not create EGL image, err = (0x3002)` followed by
`Failed to create a valid texture ... [640,480] isProtected:1 ... format:2141391878`.
The stack reaches GaneshBackendTexture. Init then killed zygote and restarted
the framework; kernel uptime continued. This is distinct from r36's abrupt
whole-device restart. Successful preview is not successful face enrollment or
authentication, and the enrollment stall's cause is not yet established.

This boot also exposed a persistent charging-node initialization race. Init's
post-fs-data wait ended at kernel time 14.125671 after 10 seconds, while the
battery_charger probe only started at 17.613411 and finished at 17.629667.
The system-server startup ANR waited inside ChargingControlController for the
declared service. Restoring input_suspend ownership to 1000:1000 and mode 0660
allowed health services to register and startup to complete. The node's value
remained 0. Because a temporary permission correction was needed, r37 persistent
startup is not accepted. The driver depends on PMIC GLINK/ADSP readiness; module
readiness alone does not establish that this class attribute exists.

Evidence remains outside Git in reports/device/r37-face-runtime-20261108:
anr-boot.txt, kernel-after-enrollment.txt, logcat-after-enrollment.txt and
surfaceflinger-tombstone.txt. No camera was opened or image captured by the
diagnostic agent. Raw authentication tokens are not included in this report.

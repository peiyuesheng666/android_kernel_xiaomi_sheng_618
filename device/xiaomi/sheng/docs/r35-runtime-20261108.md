# r35 face camera runtime

The guarded r35 postboot readback on ca10ede3/b verified seven partition hashes,
both policy payload hashes, the face preview resource values and original
SystemUI. SELinux remained Enforcing. Evidence: reports/device/r35-20261108-130502.

The user reported a black preview without an immediate error. Fresh enrollment
logs showed camera 1 opened and reached its first image-reader GraphicBuffer
allocation. mifaced then aborted with "Failed to load matching allocator for
mapper version 4". Simultaneous SELinux denials blocked calls to servicemanager
and lookup of hal_graphics_allocator_hwservice. The AIDL frontend later aborted
when cancellation attempted a HIDL call to the dead implementation. These
records establish that r35 resolved the camera callback blocker, but face
enrollment and authentication still failed.

Evidence: reports/device/r35-face-runtime-20261108/crash.txt and
logcat-after-attempt.txt. Raw logs are excluded from Git. The r36 correction
declares the existing implementation as a standard graphics allocator client;
its separate build and policy review reports record the precise permission
delta. Working enrollment and unlock require actual postflash validation.

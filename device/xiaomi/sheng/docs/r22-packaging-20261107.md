# r22 packaging and device scope

The authorized target is ca10ede3, slot b, running the custom Android build.
A second Xiaomi Pad 6S Pro connected to this computer runs stock HyperOS for
another Recovery project. Every ADB and Fastboot action explicitly selects
ca10ede3; no action targets the other device or that project's processes.

The packer starts ODM at verified r21 and system_ext at the r20-compatible r19
base. The latter removes the obsolete r21 classpath fragment by construction.
Only the declared Settings/provider overlays, classpath JAR/init/binary and
required system_ext policy/context/cache files may change. ODM's precompiled
policy and its system_ext digest update with the source policy. Vendor retains
r21's verified physical-DPI correction. Both AVB parent chains are verified.

New EROFS APKs require an explicit certificate pin; existing APKs must retain
their previous certificate. The provider overlay pins the same test certificate
as the existing Settings overlay. New node ownership, mode and SELinux labels
come from compiled contexts and fs_config. Metadata and all undeclared content
must match the respective baseline.

The flash helper validates the local batch and six exact installed r21 hashes,
then requires Fastbootd product sheng and slot b before writing the four declared
images. It never invokes adb root itself. Announce adb root and its expected
short reconnect before invoking it; announce the planned reboot before flash.
Final build, image and runtime receipts record actual validation outcomes.

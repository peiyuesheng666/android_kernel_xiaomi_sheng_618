# r15 corrected hardware-color batch

This batch resumes the rejected r14 display work on the verified r13 baseline.
The corrected owning-container SDM adapter passed a temporary hardware trial:
RGB changed the DSPP PCC coefficients and the user confirmed a visible change.
Both packaging and flashing now require the exact tested library SHA256
`d3908ae8be949614ad63a0b884927bb390df6e9327771a5ae0905c212c0fa303`.
The rejected byte-view library cannot satisfy that guard.

Only the ODM Framework/Settings overlays, vendor lib64/libsdmcore.so and their
vbmeta parent are in scope. A new revision-15 frozen spec and an exclusive new
output directory preserve all failed r14 artifacts and the r13 rollback images.
Metadata, filesystem and AVB checks remain mandatory; live flashing also
verifies all six r13 baseline hashes, device sheng and current slot b.

The batch provides the standard color-mode menu and sensor-based display white
balance in addition to the corrected hardware RGB/Night Light path. Ambient
adaptation and persistent boot acceptance still need testing. No screenshot,
camera/AON activation or GPU fallback is part of this work. Keyboard and touch
candidates remain paused and are not included.

Validation before committing the tools: PowerShell parse, Python compile,
packaging regression fixtures and owned-container ASan/UBSan coverage. Build,
image publication and hardware acceptance are recorded separately below when
actually completed.

The parse/compile checks, all 12 packaging-helper cases and the ABI sanitizer
case passed. Publication on the actual artifacts mount passed nine cases;
three were skipped because this volume rejects reparse creation (Win32 1392)
or the optional dedicated Junction fixture parent was not supplied. The normal
publication, corruption, destination race and no-overwrite cases ran.
Tracked non-document device sources were synchronized and byte-verified in
WSL; only the two r15 packaging/flash tools differed before that sync.

## Integration build and source verification

The installed vendor/lib64/libsdmcore.so target and both overlays completed
the integration build in 01:35. Ninja found the previously compiled corrected
inputs up to date; this was dependency/install verification, not a new full-ROM
compile. The first attempt rejected an unexposed prebuilt module target, and
the successful retry used the actual installed path. Both logs are retained.
The generated Soong compiler was restored to its original ELF output.

Before and after the successful build, 13 public repositories were fetched at
their fixed upstream revisions and physically verified, and all 1,243 project
statuses were clean. The core output equals the tested owning-adapter hash.
APK resource readback confirms modes [0,1,2], requested Chinese labels, DWB
availability/default=true and xiaomi.sensor.front_cct. Details are in
build-r15-20261107.json and prebuild/postbuild-r15-upstream-audit.json.
Both the original failed r14 spec and a copy relabelled as r15 were rejected
by the new packaging guard without writing any image.

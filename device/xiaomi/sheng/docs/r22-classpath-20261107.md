# r22 ordered tablet compatibility classpath

r21 put the Xiaomi compatibility JAR between platform and APEX jars. Existing
boot images retain the original order, and normal app UIDs could not load the
class even though the zygote environment contained the JAR. An isolated process
loads miui.os.Build.IS_TABLET=true when the JAR follows every original boot jar
and DEX2OATBOOTCLASSPATH remains unchanged.

The device-owned native adapter runs the unmodified official generator, then
appends only BOOTCLASSPATH. It preserves every other export byte, writes a
separate file and renames it after a successful write. Adapter errors retain
the valid official output. Official-generator failures propagate. The service
uses the existing derive_classpath domain; a device system_ext policy permits
that domain to execute the official generator without a new transition. The
binary has the standard derive_classpath_exec label. Corresponding compiled
policy and cache hashes must be packaged together.

The initial native build passed; two host tests verify full platform/APEX prefix
preservation, unchanged DEX2OAT and other exports, and rejection of duplicate or
malformed input. Ordinary app UID and actual Douyin acceptance are still pending.
This class provides only the tablet flag, not a general MIUI framework.

## Final acceptance

The final compiled artifacts and r22 runtime checks passed. See
r22-runtime-20261107.md for ordinary-UID results, user confirmation and the
precise default-name validation scope.
